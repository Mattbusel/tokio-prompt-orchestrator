Model routing: which upstream answers which model name.

A static [[models]] table maps model names, or globs such as gpt-*, claude-* or llama-*, to providers. Each route gets its own pipeline (queue, circuit breaker, timeout, retries, concurrency limit), so a failing provider only opens its own breaker.

# models.toml, or the same tables inside a pipeline TOML
default_route = true        # unknown models go to --provider/--model (the default)

[[models]]
name = "gpt-*"              # glob: * is any run of characters, ? one character
provider = "openai"         # any OpenAI-compatible server
# base_url = "https://openrouter.ai/api/v1"
# api_key_env = "OPENROUTER_API_KEY"

[[models]]
name = "claude-*"
provider = "anthropic"
max_tokens = 8192           # sent when the client gives no max_tokens

[[models]]
name = "llama-3.1-8b"       # an exact name
provider = "llama_cpp"
base_url = "http://gpu-box:8080"

Matching is case-insensitive. Exact names are tried first, then globs in table order. A glob route sends the client’s model name upstream; set model on a route to send a fixed name instead.

With default_route = true (the default) a model that matches no route, or no model at all, goes to the server’s own pipeline: the single --provider / --model the orchestrator was started with, exactly as before routing existed. With default_route = false such a request is answered 400 with the list of configured models.

Load a table with ModelRoutesConfig::from_file (the CLI’s --models <file>) and start its pipelines with ModelRoutes::spawn; hand the result to the web server through web_api::ServerConfig::model_routes.
