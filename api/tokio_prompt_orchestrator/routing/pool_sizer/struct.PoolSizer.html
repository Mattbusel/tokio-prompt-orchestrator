pub struct PoolSizer { /* private fields */ }
Expand description

Adaptive pool sizer.

Call observe every time you sample the queue depth, then call recommend to get a scaling decision.

§Thread safety

PoolSizer is Send + Sync. The EWMA state is protected by a Mutex but the lock is held for nanoseconds. Scale counters use atomics.

§Panics

No method panics.

pub fn observe(&self, fill_rate: f64, _channel_capacity: usize)

Feed a new queue depth observation.

§Arguments
  • fill_rate — Current queue fill fraction in [0.0, 1.0]. Typically current_depth as f64 / channel_capacity as f64.
  • _channel_capacity — Ignored; reserved for future hysteresis calculations. Pass the actual channel capacity for forwards compatibility.
§Panics

Does not panic.

Source

pub fn recommend(&self) -> ScaleRecommendation

Return a scaling recommendation based on the current EWMA.

Applying the recommendation is the caller’s responsibility. After acting on a scale-up or scale-down, call apply_scale so the sizer tracks the new pool size.

§Panics

Does not panic.

Source

pub fn apply_scale(&self, new_worker_count: usize)

Inform the sizer that a scale action has been applied.

Call this after your orchestration code has actually added or removed workers. The sizer uses this to reset the cooldown counter and track the current pool size.

§Arguments
  • new_worker_count — The actual new pool size after the scale action.
§Panics

Does not panic.
