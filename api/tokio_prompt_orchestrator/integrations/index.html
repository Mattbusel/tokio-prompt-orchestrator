Use the orchestrator with the Rust LLM crates you already have.

Each integration is its own cargo feature, off by default, so you only compile the one you use. They all produce a ModelWorker, so the deduplication, circuit breaker, retries, timeouts and dead-letter queue work the same whichever client sits underneath.

FeatureTypeWraps
async-openai[AsyncOpenAiWorker]an [async_openai::Client] you configured: OpenAI, Azure OpenAI, or any OpenAI-compatible server
genai[GenaiWorker]a [genai::Client]: OpenAI, Anthropic, Gemini, Ollama, Groq, DeepSeek, xAI, Cohere and more, picked by model name
rig[RigWorker]any rig 0.43 to 0.46 agent or model that implements rig::completion::Prompt (needs Rust 1.95; rig 0.45 and 0.46 need 1.97.1)
rig-transport[OrchestratedTransport]the transport under any rig 0.45 or 0.46 model: dedup, circuit breaker and retry, with the full rig request (messages, tools, params) passed through unchanged (needs Rust 1.97.1)
tower[ServiceWorker], [WorkerService]any tower::Service<String>, in both directions

Or skip the pipeline and put the dedup and circuit breaker straight into the client stack you already have. These two also ship on their own as the llm-resilience crate, for projects that want only them (its core depends on tokio, parking_lot and tracing):

FeatureTypeWraps
tower[ResilienceLayer]any tower::Service (HTTP client, LLM client, gRPC channel): single-flight dedup by a key you choose, plus a circuit breaker
reqwest-middleware[ResilienceMiddleware]a reqwest_middleware::ClientWithMiddleware (reqwest 0.12, reqwest-middleware 0.4): identical in-flight requests share one upstream call, and a circuit breaker per host

A Retriever that grounds prompts in your documents:

FeatureTypeSearches
tantivy[TantivyRetriever]a folder of Markdown/text files, BM25 full-text, in memory (needs Rust 1.90)

fastembedFastEmbedderlocal ONNX models on the CPU, no API key (needs Rust 1.88)

genai[GenaiEmbedder]any provider genai supports embeddings for
