What your LLM logs say you paid for twice.

You pay for the same prompt twice. Identical requests go out while the first is still in flight, the same request is sent again a minute after it was answered, a 400 is retried as if the next attempt could pass, and retries during an outage are capped by count while each one bills a full context. None of it shows on a dashboard that sums tokens per day.

analyze replays a request log and prices each of those:

CategoryWhat it isWhy it is waste
in_flight_duplicatean identical request started before the first one finishedone call could have served both
repeat_within_ttlan identical request within the TTL (default 5 min) after a successthe answer was already paid for
retry_after_4xxthe identical request sent again after a non-retryable 4xxa 400/401/403/404/422 fails the same way again
retrythe identical request sent again after a 408/409/429/5xx/529legitimate, but capped by count it has no ceiling in dollars; the report shows what a dollar budget would have refused
agent_repeatan agent step that repeated the previous action and got the identical observation backa full-context call that learned nothing

Records are JSON objects, one per line (JSONL) or a JSON array. Field names from common gateways and SDK logs are recognised (OpenAI-style request/response logs, LiteLLM spend logs, Helicone and Langfuse exports): see Call::from_value. Prices come from the log’s own cost field, else from [llm_prices] list prices for the model, else the call is counted but left unpriced.

audit_source is the static half: it reads retry code and flags retries with no dollar ceiling, retries on every exception (4xx included) and retry loops that never stop.

The burn binary (feature cli) runs both from the command line.

Functions§

analyze
Replay calls (in any order; they are sorted by start time) and price every duplicate, repeat and blind retry.
audit_source
Scan one source file for retry code that can burn money: tenacity and backoff decorators (Python), retry loops that catch every exception, and count-only retry settings. path picks the language by extension (.py, .ts, .js, .mjs, .rs, .go); other files give nothing.
parse_log
Parse a log: JSONL (one object per line) or one JSON array. Returns the calls and the number of records skipped.
