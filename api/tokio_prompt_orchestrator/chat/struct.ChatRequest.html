Expand description

One chat completion request, in OpenAI Chat Completions terms.

messages holds the client’s message objects unchanged (role, content, and for tool use tool_calls, tool_call_id, name). All settings are optional; a worker sends only the ones that are set, and falls back to its own configured defaults for the rest.

§Examples

use serde_json::json;
use tokio_prompt_orchestrator::ChatRequest;

let mut req = ChatRequest::new("gpt-4o-mini", vec![json!({"role": "user", "content": "Hi"})]);
req.temperature = Some(0.0);
req.max_tokens = Some(64);
assert!(req.is_cacheable());
assert_eq!(req.transcript(), "Hi");

pub fn has_tools(&self) -> bool

true when the request defines at least one tool. Without tools, tool_choice and parallel_tool_calls mean nothing and are not sent upstream (OpenAI answers 400 for either one without tools).

stop as a list (a single string becomes a one-element list).

Source

pub fn is_cacheable(&self) -> bool

true when a completed answer may be reused for an identical request that arrives later. A request with temperature > 0 and no seed asks for a fresh sample each time, so it is only shared with identical requests that are still in flight. Without a temperature (the provider’s default) or with a seed, the answer is reusable.

Source

pub fn dedup_key(&self, route: &str) -> String

Deduplication key: SHA-256 (hex) over a canonical encoding of route, the model, the messages, the tools and tool choice, every sampling setting and the response format.

Object keys are sorted at every level, so field order does not matter; any difference in content or settings gives a different key. route names the upstream the request goes to, so the same model name served by two routes never shares an answer.

§Examples
use serde_json::json;
use tokio_prompt_orchestrator::ChatRequest;

let msgs = vec![json!({"role": "user", "content": "Hi"})];
let mut a = ChatRequest::new("gpt-4o", msgs.clone());
let mut b = ChatRequest::new("gpt-4o", msgs);
assert_eq!(a.dedup_key("default"), b.dedup_key("default"));
b.temperature = Some(0.9);
assert_ne!(a.dedup_key("default"), b.dedup_key("default"));
a.temperature = Some(0.9);
assert_eq!(a.dedup_key("default"), b.dedup_key("default"));
Source

pub fn settings_fingerprint(&self, route: &str) -> String

SHA-256 (hex) over the settings alone (everything in dedup_key except the messages). Requests with the same fingerprint differ only in what they say; semantic deduplication compares prompts only within one fingerprint.

Source

pub fn transcript(&self) -> String

The conversation flattened into one prompt, for workers that take a single string. A lone user message is returned exactly as written; anything longer becomes a Role: text transcript separated by blank lines. Only text content is kept.

Source

pub fn to_openai_body( &self, model: &str, temperature: Option<f64>, max_tokens: Option<u32>, ) -> Value

The request as an OpenAI Chat Completions body. model fills in an empty model; temperature and max_tokens are the worker’s own defaults, used only when the request leaves them unset. Without tools (see has_tools), tools, tool_choice and parallel_tool_calls are left out.
