Module single_flight

A generic single-flight primitive: concurrent calls with the same key run the work once and all get the result.

Dedup<K, V> works for any key and any cloneable value, so it is just as useful for database lookups, token refreshes, config fetches or image renders as it is for LLM calls. It has no dependency on the rest of the pipeline.

use std::sync::atomic::{AtomicUsize, Ordering};
use std::sync::Arc;
use std::time::Duration;
use tokio_prompt_orchestrator::Dedup;

let dedup: Dedup<String, u64> = Dedup::new();
let calls = Arc::new(AtomicUsize::new(0));

let fetch = |id: &str| {
    let calls = calls.clone();
    dedup.run(id.to_string(), move || async move {
        calls.fetch_add(1, Ordering::SeqCst);
        tokio::time::sleep(Duration::from_millis(20)).await;
        42
    })
};

// Three concurrent calls for the same key: one fetch.
let (a, b, c) = tokio::join!(fetch("user:7"), fetch("user:7"), fetch("user:7"));
assert_eq!((a, b, c), (42, 42, 42));
assert_eq!(calls.load(Ordering::SeqCst), 1);

§Semantics

  • One leader per key. The first caller for a key runs its closure. Callers that arrive while it runs wait for its result instead of running their own. Once the leader finishes, the key is free again: the result is not cached (put a cache in front if you want one).
  • Cancellation is safe. If the leader’s future is dropped (a timeout, a client disconnect) or its closure panics, the waiters are woken and one of them becomes the new leader and runs its own closure. Nobody waits forever and no panic is propagated to the waiters.
  • Errors are values. Use V = Result<T, E> (with E: Clone, or an Arc<E>) and the waiters get the leader’s error too, which is usually what you want during an outage.
  • No 'static or Send bound on the work. The leader’s future runs inline in the leader’s task, so it may borrow from its caller.
