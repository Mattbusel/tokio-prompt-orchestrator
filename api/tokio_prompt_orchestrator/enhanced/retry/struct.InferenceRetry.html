Expand description

Retry settings for the pipeline’s inference stage.

Every model call made by the pipeline goes through InferenceRetry::run. With max_retries == 0 (the default for spawn_pipeline) the call is made exactly once. Otherwise a call that fails with a transient error (429, 5xx, network) is retried with jittered exponential backoff, and a provider’s Retry-After is respected when it is no longer than max_delay. Errors that cannot succeed on a retry (bad key, budget exceeded, bad config) are returned at once.

All attempts of one request count as one call for the circuit breaker, and all of them together must fit in the inference timeout.

§Retries cost money, so they are capped in money

A retry count says nothing about what the retries cost: three retries of a 200,000-token agent context on a frontier model are dollars, and during an outage every request retries at once. With a RetryBudget set (with_budget, on by default in the orchestrator binary), each retry must first be paid for from a dollar budget (a floor plus 10% of the pipeline’s real spend per hour, see [llm_resilience::RetrySpend]). A retry that does not fit is not sent: the request fails with the error it already has. max_retries stays as an upper bound on attempts.

§Examples

use std::time::Duration;
use tokio_prompt_orchestrator::enhanced::InferenceRetry;

let retry = InferenceRetry::new(2, Duration::from_millis(200), Duration::from_secs(5));
assert!(retry.is_enabled());
assert!(!InferenceRetry::disabled().is_enabled());

Fields§

§max_retries: u32

Retries after the first attempt. 0 disables retrying.

§base_delay: Duration

Delay before the first retry; it doubles on each further retry.

§max_delay: Duration

Cap on the backoff delay, and on how long a Retry-After may ask the stage to wait. A longer Retry-After fails the request instead.

§budget: Option<RetryBudget>

Dollar budget every retry must fit in. None caps retries by count only.
